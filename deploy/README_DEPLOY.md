# 项目服务器 Docker 生产部署指南（宝塔面板专用）

本指南专为 **宝塔面板（BT-Panel）** 环境下的 **全栈 Docker 容器化部署** 定制。  
服务器公网 IP：`YOUR_SERVER_IP`（请替换为您自己服务器的真实公网 IP 或解析后的域名）

---

## 一、 系统架构与端口规划

本项目采用 **前后端分离 + 全 Docker Compose 编排** 架构。针对宝塔面板已占用常见端口（如 80、81、3306 等）的现状，进行了无缝隔离设计：

| 服务名称 | 容器名称 | 宿主机映射端口 | 容器内网络 | 访问地址与说明 |
| :--- | :--- | :--- | :--- | :--- |
| **用户端前台门户** (`front-web`) | `snowy-front-web` | **8080** | 内置 Nginx | `http://<YOUR_SERVER_IP>:8080` (学生端系统) |
| **管理端后台系统** (`admin-web`) | `snowy-admin-web` | **8081** | 内置 Nginx | `http://<YOUR_SERVER_IP>:8081` (管理后台系统) |
| **后端 Spring Boot 服务** | `snowy-backend` | **无需映射** | 容器内 82 | **仅 Docker 专有内网互联，不对外暴露** |
| **MySQL 8.0 数据库** | `snowy-mysql` | **13306** (可选) | 容器内 3306 | 容器间内网互联，映射 13306 仅方便 Navicat 调试 |
| **Redis 7 缓存服务** | `snowy-redis` | **无需映射** | 容器内 6379 | **仅 Docker 专有内网互联，不对外暴露** |

### 💡 核心解答：为什么不需要放开 82 端口？
> **用户疑问**：后端在 Docker 里，为什么还要放开 82？
> 
> **回答：不需要放开 82！**
> 1. **全链路内网闭环**：浏览器访问的是前端（8080/8081），当浏览器发起 `/api/*` 请求时，请求到达前端容器内的 Nginx。
> 2. **Docker 内部域名通信**：前端 Nginx 接收到请求后，通过 Docker 内部虚拟局域网（`snowy-network`），直接在容器内网将请求转发给 `http://snowy-backend:82`。
> 3. **极高安全性**：
>    - 后端 Spring Boot 82 端口、Redis 6379 端口完全不需要映射到宿主机，更**不需要在云厂商安全组和宝塔防火墙中放行**！
>    - 彻底杜绝了外部黑客直接扫描后端接口或暴破数据库/Redis 的安全隐患。
>    - 您的云服务器只需要对外放开 **`8080`** 和 **`8081`** 两个前端端口即可！

## 二、 部署前准备（仅需 2 步）

### 1. 云平台安全组与宝塔防火墙放行端口
请在服务器提供商（阿里云 / 腾讯云等）的**安全组**以及宝塔面板的**『安全』**菜单中放行：
- **`8080`**（前台学生门户）
- **`8081`**（后台管理系统）
- **`13306`**（可选：仅当您需要用本机 Navicat 直连数据库时放行）

*(注：82、6379、3306 均在 Docker 内部闭环，完全无需放行！)*

### 2. 宝塔面板安装 Docker
1. 登录宝塔面板后台。
2. 点击左侧菜单 **『Docker』**。
3. 若提示未安装，点击提示框中的 **『一键安装』** 即可（宝塔会自动配置好 Docker 与 Compose 环境）。

---

## 三、 上传与一键部署

### 步骤 1：上传项目压缩包
1. 打开宝塔面板，进入 **『文件』** 菜单，进入目录 `/www/wwwroot/`。
2. 创建项目目录：`/www/wwwroot/st_homework_manage`。
3. 将项目根目录下的 **`deploy.zip`** 上传到此目录并点击 **『解压』**。

### 步骤 2：终端一键启动
在宝塔面板打开右上角 **『终端』**（或使用 SSH 连接服务器），执行以下命令：

```bash
# 1. 进入部署目录
cd /www/wwwroot/st_homework_manage

# 2. 赋予脚本执行权限
chmod +x deploy.sh

# 3. 运行一键构建与部署
./deploy.sh up
```

*(或者直接执行：`docker compose up -d --build`)*

容器启动过程全自动化：
- MySQL 容器首次启动时会自动读取并执行 `db/init.sql`，完成数据库和底座结构初始化。
- 依赖编排保证 MySQL、Redis 准备就绪后，后端 `snowy-backend` 与双前端容器依次拉起。

## 五、 常用日常运维指令

在服务器 `/www/wwwroot/st_homework_manage` 目录下：
- **查看服务运行状态**：`./deploy.sh ps`
- **查看所有服务实时日志**：`./deploy.sh logs`
- **单看后端 Spring Boot 实时日志**：`docker logs -f --tail 200 snowy-backend`
- **重启全部服务**：`./deploy.sh restart`
- **停止服务**：`./deploy.sh down`
- **用户上传文件存放位置**：位于宿主机 `./data/upload`（作业、头像、竞赛附件等持久化存储，容器重建不丢失）。
